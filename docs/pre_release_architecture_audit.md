# A股量化平台发布前架构与测试审计

审计日期：2026-07-20

> 本文是技术、产品和运营风险规划，不构成法律、证券投资或税务意见。

## 一、当前结论

- 本地核心程序可在 `127.0.0.1:8501` 启动，健康检查返回 `200 ok`。
- 自动化测试共 42 项，当前全部通过。
- 发布包已加入文件清单和 SHA256 校验，部署前后均会执行自检。
- 系统可以用于管理员本人及 2-5 名受邀用户的免费封闭测试。
- 在生产 MySQL 凭据、行情新鲜度和合规路径未通过前，不应对外收费上线。

## 二、已修复问题

### P0 已完成

1. 生产环境关闭登录的风险
   - 新增 `APP_ENV` 环境隔离。
   - 生产环境若未开启登录，发布检查直接失败。

2. 数据库结构不完整但程序仍启动
   - 发布检查会验证 MySQL 连接、核心表、关键字段和视图。
   - 数据库异常信息脱敏，避免把密码或完整连接串显示给用户。

3. 过期推荐仍被当作今日推荐
   - 按工作日计算推荐数据新鲜度。
   - 页面显示过期、缺失或日期异常提示。

4. 手工订单数据可被伪造或误录
   - 校验订单编号、会员编号、金额、支付渠道、套餐状态和删除状态。
   - 价格不一致时记录审核备注。

5. Webhook 地址泄露密钥
   - 管理页面仅显示脱敏地址。
   - 网络异常日志不再直接输出敏感 URL。

6. 更新包可能缺文件或被篡改
   - 发布包包含 SHA256 文件清单。
   - 部署脚本验证源文件和部署后文件哈希，不一致即停止并回滚。

7. 本地与服务器启动参数互相污染
   - 本地脚本固定使用 `APP_ENV=local` 和免登录调试。
   - 服务器脚本固定使用 `APP_ENV=production`，且要求登录开启。

8. 日志不可追踪
   - 新增 UTF-8 轮转应用日志。
   - 部署、健康检查和运行异常均有固定日志目录。

## 三、上线阻断项

### P0 必须完成

1. 修复生产 MySQL 登录
   - 当前环境自检曾返回 MySQL `1045 Access denied`。
   - 重新设置数据库账号密码后，必须运行完整发布检查。

2. 刷新行情和推荐快照
   - 当前最新推荐日为 2026-07-15，按审计日计算已过期 3 个工作日。
   - 对外测试前必须生成当日或最近交易日快照，并核对股票总数和覆盖率。

3. 建立版本基线
   - 当前 Git 仓库没有首个提交和版本标签。
   - 上线前创建基线提交、发布标签，并保留对应 ZIP 和 SHA256 清单。

4. 验证数据库恢复
   - 不能只验证“备份文件生成”。
   - 应在临时库完成一次恢复演练，核对会员、推荐、持仓和订单记录。

5. 建立数据库迁移机制
   - 当前以完整 SQL 建库为主，后续字段变更容易造成服务器和本地结构漂移。
   - 增加 `schema_migrations` 表和按版本执行的增量 SQL。

6. 完善账号安全
   - 增加管理员重置密码、强制下线、登录失败次数限制和会话撤销。
   - 服务器密钥放入环境变量或 Windows 凭据存储，不写进源码和发布包。

7. 确认行情数据授权
   - 免费接口能否用于多人展示、缓存和收费产品，需要按数据源条款确认。
   - 未确认前只做个人或免费封闭测试。

## 四、仍需重点测试

1. 登录：正确密码、错误密码、停用、删除、过期、并发登录、会话撤销。
2. 推荐：空数据、部分数据源失败、重复刷新、非交易日、日期跨年。
3. 条件选股：价格上下限、随机价格、条件互斥、零结果和超时。
4. 个股分析：代码/名称/简称搜索、停牌、退市、上市不足 120 日。
5. 持仓中心：保存、修改、移除、零可卖底仓、行情中断和重复生成。
6. 回测：前复权口径、手续费、印花税、涨跌停无法成交、T+1 和停牌。
7. 预警：重复触发、静默时段、失败重试、过期规则和用户隔离。
8. 管理后台：开通、续期、退款、套餐变更、删除恢复和审计记录。
9. 部署：断电重启、任务计划失败、端口占用、回滚和备份恢复。
10. 移动端：390px 宽度下表格、日期、标签页、按钮和错误提示。

## 五、后续开发计划

### 阶段 A：发布加固（1-2 周）

- 完成全部上线阻断项。
- 引入数据库迁移、备份恢复演练和版本标签。
- 增加密码重置、会话撤销、限流和安全审计。
- 增加数据源状态页：更新时间、延迟、覆盖率、备用源和失败原因。
- 验收标准：生产发布检查全绿，连续 5 个交易日自动任务无中断。

### 阶段 B：免费封闭测试（2-4 周）

- 仅邀请 2-5 名熟人，不收费、不承诺收益、不公开推广。
- 建立用户反馈、错误编号和操作审计。
- 扫描任务移到后台，页面只读取已完成快照。
- 完善组合风险：行业集中度、单股风险、相关性和最大风险预算。
- 验收标准：关键页面成功率不低于 99%，异常均能定位到日志。

### 阶段 C：付费沙箱与合规评估（并行 2-4 周）

- 定义统一 `PaymentProvider` 接口，先接内部模拟支付或 Creem Test Mode。
- 实现签名验证、幂等键、重放防护、订单状态机、取消和退款测试。
- 沙箱支付只验证链路，不收真实资金，也不自动开放正式付费会员。
- 咨询证券合规律师或持牌证券投资咨询机构，确认产品边界、文案和合作方式。
- 确认行情数据的商业授权及个人信息保护要求。

### 阶段 D：具备合规条件后商业上线

- 由符合要求的经营主体和持牌/合作主体承接收费服务。
- 接入真实支付、退款、取消订阅、账单和对账。
- 保存用户协议、隐私政策和风险揭示的版本及同意时间。
- 建立监控、告警、限流、灾备和安全测试。

## 六、适合继续上线的产品能力

1. 推荐可信度校准
   - 同时显示样本数、胜率置信区间、T+1/T+3/T+5/T+20、最大回撤和模型版本。

2. 样本外回测
   - 增加滚动训练、样本外验证、基准比较和参数稳定性，避免只展示历史拟合。

3. 数据血缘
   - 每条推荐可追溯到数据时间、来源、复权方式、策略版本和筛选参数。

4. 交易日志与复盘
   - 用户记录实际买卖后，对比计划、执行价、滑点和错误原因。

5. 组合级风险
   - 不只分析单股，增加总仓位、行业暴露、相关性、回撤预算和压力测试。

6. 可解释提醒
   - 每次提醒必须同时给出触发条件、失效点、风险和数据时间。

## 七、付费与主体建议

### 当前最稳妥方案

- 使用免费、邀请制、封闭测试。
- 账号由管理员手工开通，不把转账与功能权限绑定。
- 用模拟订单或 Creem Test Mode 测试订阅全链路，不发生真实扣款。

### 不建议的做法

- 不用个人收款码、红包或“赞赏”变相绑定会员权限。
- 不因人数少或只卖给熟人，就假设无需证券业务许可。
- 不在闲鱼、微信群或公开网页宣传“荐股、必涨、稳赚、回本”。
- 不因支付平台支持支付宝结算，就认为产品已满足经营或证券合规要求。

### 原因

- 证监会公开答复指出，提供具体证券分析、价格预测、选股或买卖时机的软件，
  并直接或间接取得经济利益，可能属于证券投资咨询业务，需要相应许可。
- 网络小额交易的市场主体登记例外，不适用于依法需要行政许可的经营活动。
- Creem 正式商户条款要求符合适用法律的企业或自雇主体，并限制需要许可的金融服务；
  中国个人支付宝收款能力只是结算通道，不替代经营和行业许可。
