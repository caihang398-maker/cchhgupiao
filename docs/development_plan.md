# 量化选股系统开发计划

## 目标与边界

- 商业版继续提供选股、复盘、持仓、预警、模拟交易和会员服务。
- 个人交易模块仅管理员可见，并由 `ENABLE_PERSONAL_TRADING` 单独启用。
- 东吴 QMT 未审批前只做行情分析、订单草稿和风控演练，不提交真实委托。
- 所有结论使用概率、条件、风险和失效点表达，不承诺收益。

## 第一阶段：稳定性与可用性（已完成）

- 行情访问自动尝试直连和系统代理。
- 龙头曲线增加同板块推荐池、本地行情快照和上次成功结果降级。
- 数据源异常改为局部提示，不阻断其他页面。
- 分钟行情增加最近成功快照缓存。
- 发布前覆盖核心测试和 Streamlit 页面启动测试。

## 第二阶段：交易前风控底座（已完成）

- 独立订单台账，记录草稿、提交、失败和券商订单号。
- 独立风险状态：总熔断、单笔金额、单日亏损、单日委托数、单股集中度。
- 订单风险检查与券商适配器解耦。
- 账号仅保存脱敏信息，不保存交易密码。

## 第三阶段：商业产品体验（下一批）

1. 数据源状态中心：延迟、覆盖率、成功率、缓存时间、备用源状态。
2. 推荐解释统一化：入选证据、反向证据、失效条件、历史样本量。
3. 持仓中心任务化：今日动作、风险优先级、方案变化、执行记录。
4. 预警闭环：触发、确认、忽略、失效、结果复盘。
5. 移动端：首屏只保留今日建议、持仓风险和重要预警。
6. 管理后台：会员到期、续费、数据源异常、任务失败和使用活跃度。

## 第四阶段：东吴 QMT 审批后

1. 在单独测试账号和模拟环境验证查询、委托、撤单、回报回调。
2. 校验交易时段、涨跌停价格、停牌、最小交易单位、可卖数量和重复委托。
3. 增加成交回报对账、断线重连、未知订单状态和人工接管。
4. 连续模拟至少 20 个交易日后，才允许管理员手工开启实盘开关。
5. 自动交易仍需二次确认、总熔断和完整审计日志。

## 微信小程序专项（进行中）

### 已完成

1. 小程序前端与 `8512` API 独立部署，PC 端 `8501` 保持原样。
2. 微信快捷登录、首次自动创建体验账号、OpenID 复用登录和账号密码备用登录。
3. 会员到期后允许进入订阅页，但拦截推荐、持仓、预警等会员接口。
4. 月卡、季卡、半年卡、年卡展示，以及个人主体虚拟支付资格检查。
5. 微信开发者工具 CLI 已接通，本机接口、页面结构、JSON、JavaScript 和事件绑定检查已通过。

### 等待账号资料后实施

1. 使用真实 `wx...` AppID 完成开发者工具模拟器编译和真机调试。
2. 在微信后台确认“工具”类目、认证、备案和个人虚拟支付开通状态。
3. 配置 OfferID、现网 AppKey，并创建月/季/半年/年四个道具。
4. 开发 `wx.requestVirtualPayment` 下单签名，支付密钥只保存在服务器。
5. 部署发货推送，按微信订单号幂等发放会员天数，并增加每 5 分钟主动查单兜底。
6. 完成退款、对账、支付失败恢复、重复通知和小额真单验收后，才打开正式支付开关。

### 上线后增强

1. 首屏性能埋点、接口延迟和最近成功时间展示。
2. 经用户主动授权的订阅消息，优先发送止损、持仓风险和数据异常提醒。
3. 会员开通漏斗：进入、试用、查看套餐、发起支付、支付成功和续费留存。
4. 真机弱网、Android、iOS、Windows 微信客户端兼容性回归。

## 验收标准

- 外部单一数据源失败时，主页面仍可打开并明确显示数据时间。
- 同一订单不会因页面重运行重复提交。
- 总熔断开启后任何实盘订单都不能通过。
- 旧数据库可原地新增表，不删除或覆盖已有业务数据。
- 每次服务器更新必须通过单元测试、页面启动测试和发布前自检。
